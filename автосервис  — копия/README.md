# Ровный ход

Переиспользуемый MVP автосервиса: услуги, предварительный расчёт, корзина, форма с фото, приватная ссылка заявки и кабинет владельца. Исходная тема мебели заменена автосервисом по уточнению заказчика.

## Быстрый запуск

Нужен Node.js 22.13+ (проверено на Node 26.13). В папке проекта:

```sh
npm install
npm run setup
npm run dev
```

Открыть адрес Local, который напечатал сервер. Обычно это **http://127.0.0.1:3000**. Если порт занят, Next может выбрать **http://127.0.0.1:3001**: открывайте именно его. Кабинет: **http://127.0.0.1:3000/admin**. Пароль находится в `.env.local`, строка `OWNER_PASSWORD`. Команда setup не меняет уже существующий файл и не печатает пароль в лог. Демо-заявок в основной базе нет. При смене пароля в кабинете значение из env больше не используется: действующий хеш хранится в базе.

Локальная база: `.data/rovny.sqlite`. Не удалять при перезапуске. Резервировать средствами SQLite либо при остановленном сервере вместе с WAL. После сборки перезапустите `npm start`; во время разработки используйте `npm run dev`. Разработка использует отдельную папку `.next-dev`, production-сборка — `.next`. Это предотвращает потерю CSS/JS при сборке во время разработки. Если видна только HTML-структура: остановите старый сервер Ctrl+C, запустите `npm run dev` и обновите страницу Command+R.

```sh
npm test
npm run typecheck
npm run build
node tests/integration.mjs
npm start
```

Интеграционный прогон использует готовую production-сборку, отдельную временную базу и вымышленные данные. Он напрямую вызывает реальные серверные обработчики без HTTP-сервера; это не браузерный E2E.

## PostgreSQL и публикация

Для serverless необходимо постоянное PostgreSQL-хранилище. Предусмотрен адаптер Supabase PostgreSQL / PostgREST без клиентского SDK:

1. Создать отдельный Supabase проект для компании и выполнить `scripts/schema.sql` в SQL Editor. Таблица закрыта RLS, anon/authenticated не имеют доступа.
2. Указать `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` только в серверных переменных. Не использовать префикс NEXT_PUBLIC.
3. Задать постоянный случайный `APP_SECRET` от 32 символов, сильный `OWNER_PASSWORD`, точный HTTPS `APP_URL`.
4. Удалить `ALLOW_LOCAL_DB=true` для serverless. Без PostgreSQL production-запросы в таком режиме намеренно не работают, вместо исчезающих данных.
5. Разместить Next.js на Node-хостинге или совместимой serverless-платформе. Фото обрабатываются sharp; нужен Node runtime. Для локальной SQLite нужен сервер с постоянным диском, не serverless.
6. За доверенным reverse proxy включить TRUST_PROXY=true только если он сам перезаписывает X-Forwarded-For. Иначе лимиты общие на экземпляр.
7. Проверить цепочку на опубликованном адресе и настроить резервные копии, срок хранения и ежедневное удаление истёкших технических записей. SQL-примеры очистки в schema.sql.

Для публичного запуска обязательны реальные контакты, юридические данные оператора в политике, согласованные цены, домен и территориально подходящее хранение персональных данных. Эти сведения не выдуманы. Текущая политика явно описывает демонстрационную установку. Контакты без настройки не ведут на фиктивный телефон.

## Расчёт

Цена варианта × количество × (1 + процент сложности), затем округление каждой строки до целого рубля. Складываем известные строки, применяем минимум только к работам, добавляем фиксированный выезд. Запчасти и расходники оцениваются отдельно. «Другая работа» не стоит ноль: отдельная ручная оценка, требуется описание и минимум одно фото. В смешанной заявке отдельно известная сумма и неопределённая часть. Полный тариф и расчёт записываются в заявку навсегда; изменение настроек не меняет прошлые заявки.

Идемпотентность: сохраняемый в черновике ключ, уникальная запись с HMAC-токеном. Повтор после потери ответа возвращает ту же заявку. Нельзя сбрасывать APP_SECRET между развёртываниями: он участвует в вычислении токена повторной отправки.

## Данные и безопасность

Фото JPEG/PNG/WebP до 8 МБ, проверка сигнатуры, декодирование sharp с пределом 40 Мп, коррекция ориентации, WebP до 1800 px. Превью хранятся в черновике, итоговые фото — отдельные записи в закрытой БД. Полные файлы выдаются только владельцу после проверки сессии, API клиента их не возвращает. Фото без заявки нужно периодически удалять по SQL из schema.sql. Base64 в PostgreSQL подходит небольшому MVP; при росте вынести изображения в приватный object storage с серверным контролем доступа.

Пароли scrypt + случайная соль; cookie HttpOnly/SameSite Strict, Secure при HTTPS. Сессия хранится в БД 7 дней. Смена пароля отзывает все сессии через версию доступа. Запросы с другого Origin отклоняются, размеры тела и частота ограничены. Публичный доступ к заявке — только по 256-битному токену. Номер для человека сам по себе ничего не открывает. Приватные заметки, контакты и фото не входят в клиентский ответ. Приватные API имеют no-store, сервис-воркер их не кеширует.

## Адаптация

Через кабинет: тарифы, минимум, сложность, выезд, имя компании, город, адрес, телефон, Telegram, часы, территория, акцент, реплика автомобиля, смена пароля. Логотип, полная палитра, тексты, PWA-иконки и дополнительные модели меняются в исходниках. Реальные юридические сведения добавляются в `src/app/privacy/page.tsx`.

Тарифные варианты не перестраивают 3D-автомобиль. Это одна иллюстративная модель, не конфигуратор запчастей. Модель без чужой марки, лица и рук. Источник `src/lib/car-geometry.mjs`, экспорт `node scripts/generate-model.mjs`, результат `public/models/rovny-touring.glb` (~1.2 МБ, без текстур). Удалено дублирование геометрий, DPR ограничен 1.5, рендер по необходимости, камера ограничена, WebGL имеет постер и повтор.

Дизайн: `design/screens.svg` — отдельный редактируемый векторный файл с ключевыми экранами. Можно импортировать в Figma. Это не нативный Figma-файл: плагин Figma не подключён. Blender/bpy не доступны, поэтому .blend не создан. Если Blender установлен: `blender --background --python scripts/blender-import.py` создаст редактируемый .blend из поставляемого GLB.

## Конкретные ограничения

- Публикация и проверка удалённого PostgreSQL не выполнены: нет настроенного проекта и серверных ключей.
- Браузерная проверка прервалась на необходимости перезапуска сервера после пересборки; полный браузерный E2E, мобильная ширина и физический телефон не подтверждены.
- Игра необязательная и в эту сборку не включена. В разделе «Игра» сохранены параметры для будущего подключения; бонусы не выдаются. Новые работы, платежи, CRM, уведомления и график мастеров требуют отдельной разработки.
- Список кабинета ограничен 1000 заявками; для роста нужна пагинация. Изменение одной заявки последним сохранением перезаписывает предыдущее; один владелец, без конкурентного редактирования.
- PWA: manifest, локальные иконки, standalone и офлайн-экран. Полноценное офлайн-оформление и фоновая отправка не реализованы.
- Нельзя считать этот исходник проверенным публичным сервисом до заполнения контактов/политики, настройки постоянной БД и приёмки на реальном размещении.

Регулярные расходы: домен, Node-хостинг, PostgreSQL, хранение/трафик фото и резервные копии. Точные тарифы зависят от провайдеров. Figma, Blender и платный LLM для работы сайта не нужны.
